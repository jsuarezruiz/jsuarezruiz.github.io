Keyframes and sequences

Use keyframes for several values on one channel. Use a sequence when several targets or independently configured steps need a shared timeline.

Evenly spaced keyframes

Pass several values and a tween. Values are spread evenly across the tween duration.

await Motion.Animate(Badge)
    .Scale(1, 1.28, 0.94, 1)
    .Rotate(0, -8, 6, 0)
    .With(Tween.EaseInOut(0.65))
    .Start();

Use MotionBuilder.Current as the first value when playback must capture the live channel state.

Offsets and segment easing

MotionKeyframe can set a normalized offset and the easing used from that keyframe to the next.

using Avalonia.Animation.Easings;

await Motion.Animate(Card)
    .X(
        new MotionKeyframe(MotionBuilder.Current, offset: 0),
        new MotionKeyframe(220, offset: 0.7, easing: new CubicEaseOut()),
        new MotionKeyframe(180, offset: 1))
    .With(Tween.Linear(0.9))
    .Start();

Use Keyframes(property, ...) for double-valued Avalonia properties.

Build a sequence

MotionSequence appends steps by default. overlap starts a step before the preceding step's estimated end.

await Motion.Sequence()
    .Add(Card, b => b.Y(-40), Tween.EaseOut(0.35))
    .Label("lifted")
    .Add(Icon, b => b.Rotate(180), Spring.Snappy, overlap: 0.2)
    .AddAt("lifted", Badge, b => b.Opacity(1), Spring.Smooth)
    .Start();

AddAt(double, ...) schedules at an absolute time without advancing the sequential cursor. The returned handle controls all sequence channels as one unit.

Steps are evaluated by their effective start time, including timing delays and WithDelay overrides. Calls to AddAt may be made in any order. Steps with the same start time keep insertion order, so the last added step writes last when they share a channel. Playback, seeking, and immediate completion use this same ordering.

When non-repeating steps overlap on one channel, each later step samples its predecessor at its scheduled start to resolve its starting value and inherited velocity. Seeking or a frame that crosses that boundary uses the same endpoints as playback through the boundary. Typed properties and MotionBuilder.Current keyframes follow this rule too.

Stagger a collection

Stagger calculates a delay from the first, last, or centre item.

for (var index = 0; index < cards.Count; index++)
{
    Motion.Animate(cards[index])
        .Y(0)
        .Opacity(1)
        .With(Spring.Smooth)
        .WithDelay(Stagger.Delay(index, cards.Count, each: 0.05, StaggerFrom.Center))
        .Start();
}
