Theming and Motion

AIKit centralizes control styles, semantic colors, typography, icons, localized strings, and animation policy in NovaTheme.

Choose a base theme

Register either Avalonia Fluent or Simple before NovaTheme:

<Application.Styles>
  <FluentTheme />
  <nova:NovaTheme />
</Application.Styles>

<Application.Styles>
  <SimpleTheme />
  <nova:NovaTheme />
</Application.Styles>

The resources use dynamic color lookups, so switching the application theme variant updates AIKit controls without rebuilding their visual trees.

Override design tokens

Place overrides after NovaTheme so they win resource resolution. Prefer semantic Nova keys over editing control templates.

<Application.Styles>
  <FluentTheme />
  <nova:NovaTheme />
  <Style>
    <Style.Resources>
      <SolidColorBrush x:Key="NovaAccentBrush" Color="#7C3AED" />
      <SolidColorBrush x:Key="NovaGreenBrush" Color="#059669" />
    </Style.Resources>
  </Style>
</Application.Styles>

The theme exposes semantic resources such as NovaCanvasBrush, NovaSurfaceBrush, NovaFieldBrush, NovaLineBrush, NovaInkBrush, and status brushes. Use them for adjacent application UI to keep custom content visually consistent.

Control motion

Animation-aware controls expose IsAnimationEnabled. Disable it on a single control when animation would distract or interfere with deterministic testing:

<nova:StreamingTextBlock StreamedText="{Binding Answer}"
                         IsAnimationEnabled="False" />

NovaMotion provides the shared motion policy used by AIKit. Controls also account for visibility and detached visual trees so background animations do not keep doing unnecessary work.

Localization and accessibility

Visible labels and automation text are resource-backed or exposed as properties. Override strings after NovaTheme or bind the corresponding text properties for application-specific language. Keep meaningful labels on source, approval, and action controls, and use the API's AccessibleName properties where a visual alone would be ambiguous.
