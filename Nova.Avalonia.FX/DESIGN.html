Design: rune audit and the Avalonia port

This is the design log: how rune-fx was audited and ported to Avalonia, the layers built beyond it, and what was measured, found wrong and changed along the way. To use the library, start with the README.

1. What rune is

rune (Anomaly, MIT, pre-release) is a Rust UI framework with its own wgpu renderer, text, layout and springs, built to run headless so an app can render to PNG and be driven by scripts. Its effects live in two crates:

  • rune-fx: effect layers (glow, pulse, electricity, fire, motion blur, distortion, shimmer, sparkles, aurora, grain) and fills (liquid metal, plastic, mesh gradient, dither, grain gradient, fluted glass, metaballs, swirl, voronoi, waves, halftone). About 19k lines including tests and examples; the shaders are about 2k lines of WGSL in 11 files.
  • rune-light: real-time lighting over the UI. It covers soft shadows, bevel normals and specular highlights, radiance-cascade GI and refractive glass. It works because every rune element is an analytic rounded rect, so the frame is already an exact 2D distance field.

2. How rune-fx works

The contract. A layer is effect params, a node shape (rounded rect, capsule or circle, in points), a time on rune's clock, a seed, a placement (under or over the node) and an opacity. Every pixel is a pure function of those. There is no hidden state and no RNG. That one rule is what makes golden images, headless rendering, slow motion, pause and stepping all work.

Rendering.

  • Each layer is one instanced quad covering the shape plus its reach.
  • Every effect family packs into the same instance struct (rect, shape, bounds, c0..c2, p0..p3, t, aux), plus a storage buffer of per-frame CPU tables.
  • A family's shader is clip.wgsl + common.wgsl + <family>.wgsl. Each module defines shade(). The common fs() applies clip, layer opacity, blend modes and the sRGB encode.
  • A pipeline is built per (family, blend, format) the first time a frame draws it, in parallel when several are needed at once. A cold Metal shader cache costs 20 to 150 ms per pipeline.

Cost is explicit.

  • prepare() culls before anything is uploaded. Silent layers get no instance, no tables and no draw: intensity 0, a fully cooled light, a one-shot outside its window, a layer off screen.
  • is_animating() tells the frame loop whether to keep ticking.
  • Every effect declares a static cost() (texture taps and noise evaluations per pixel), and the README carries a measured timing table per effect.
  • 1D functions of (time, seed) are evaluated once per frame on the CPU: bolt paths, embers, sparkles, aurora curtains, mesh points. They use the same integer hash as the GPU. That cut electricity from 9.6 ms to 0.5–1 ms on a full quad.

Animation craft.

  • Phase keeps the phase continuous when a speed changes, so the animation never jumps.
  • Heat gives a light attack and exponential cooling. Lights cool (shrink, deepen, dim) instead of cutting off.
  • OneShots<T> lets ripples, pings and zaps overlap. The pool is bounded, and when it is full the oldest instance fades out over 0.16 s.
  • Every effect has a calm reduced-motion pose with no travel.

Quality rules.

  • Math runs in linear light. Output is premultiplied, and light may exceed alpha, so it adds like a screen blend.
  • TPDF dither of ±1 LSB, static per pixel and gated to where there is signal.
  • Every light falls off analytically and is windowed inside its bounds, so no quad edge shows.
  • The integer PCG hash keeps output deterministic across GPUs.

Tooling. fill_styles() describes every fill: params with kind, range, step and unit, plus named presets. It also offers get and set by id, and to_rust(), which writes the call as the nearest preset plus the changes. Tests cover the contract: idle culling, one-shot pools, lazy pipelines, bind-group reuse and blend modes.

Why it reads as solid

  1. One small contract (a pure function of pixel, params, time and seed). Determinism, goldens, headless runs and serializable params all follow from it.
  2. Cost is a design input, not an afterthought: static declarations, measured tables, and culling built into prepare.
  3. Motion details most effect libraries skip: continuous phase, cooling lights, overlapping one-shots, and a reduced-motion pose for every effect.
  4. A shared prelude and instance layout, so each effect family is a small file.
  5. A catalog that drives inspectors and code output.

Caveats

  • Pre-release, and the project does not take pull requests. Treat it as a source of ideas and math, not a runtime dependency.
  • Tightly coupled to rune's own renderer. Effect slots, EffectSite, clip words and the backdrop copy that splits the render pass have no direct equivalent in Avalonia.
  • Its README lists its own gaps: bind groups are rebuilt every frame, fire is heavy (8 noise evaluations per pixel), the shaders have no CPU reference, and mask glow needs the caller to build a mip pyramid.
  • Additive premultiplied output (rgb > a) relies on the blend stage not clamping. Skia's paint pipeline expects valid premultiplied color, so this does not port directly.
  • rune-light assumes every element is an analytic rounded rect. Avalonia's general geometry (paths, text, images) breaks that, so it is a separate, much larger project.

3. Mapping onto Avalonia 12

Avalonia 12.1 has no public way to plug a custom shader into IEffect; only BlurEffect and DropShadowEffect exist. The extension point that does exist is the composition custom visual. It runs on the render thread, can ask for animation frames, and can lease the Skia canvas, where SkiaSharp 3.119 exposes SKRuntimeEffect (SkSL).

Deliberate divergences

  1. Float hash. SkSL runtime effects are a GLSL ES 1.0 class language with no unsigned integers or bit operations, so rune's PCG hash becomes Hoskins' sin-free float hash in the shaders. Output is still deterministic per position, but not bit-identical across GPUs. Seeds are wrapped to 0..1023 and grain frames to 1024 so the float hash keeps its quality. The CPU tables use rune's PCG exactly.
  2. Valid premultiplied output. finish() encodes light as rune does: the covering color straight × alpha, plus the light above it as over black. Alpha is then raised to the brightest encoded channel. Over dark UI this is rune's output exactly. For pure additive light, set BlendMode="Plus" or "Screen". Light surfaces. rune targets dark UI. Over white, its encoding turned faint light into a heavy wash (a radar's rings merged into a thick band) and white-hot cores vanished (stars looked hollow). So light layers (glow, pulse, sparkles, lightning) on a light surface draw as tinted haze: the light's color with its white taken out (pure white takes the layer's own color; the white is the smallest channel, taken with a smooth minimum so a blend that passes pure blue has no seam), and coverage 1 − (1 − α)·e^(−3E), which matches rune's at mid and high energy and keeps faint light faint. The radar also turns its edge glow and the wash between rings down to 0.3 there, so the rings carry it. Lightning goes further: its white-hot core, tinted to the glow's own color, blurred into the glow, so on a light surface the bolt is a crisp line in a deep shade of the color over a pale tint of its glow. FXHost.Surface picks the surface (Auto follows the host's theme).
  3. ss() for reversed smoothstep. GLSL leaves smoothstep(e0, e1, x) undefined when e0 > e1, and rune uses that form often.
  4. Clocks. A layer's time starts when it first renders; fills use one shared clock instead, so window-anchored fills on different hosts move in step. Shaders get that time wrapped forward every 4096 s (FXMath.WrapTime), so fp32 keeps it to half a millisecond after any uptime; the states step on the unwrapped clock in doubles, and the start of a ripple or a trail point is written relative to the wrapped time, so its age is exact across the wrap. FXSettings.Clock makes time absolute for snapshots. Under reduced motion, fills hold rune's CALM_T pose.
  5. Tables.
    • Uniform arrays can be indexed only by loop counters in SkSL. So bolt paths and aurora curtains travel as a raw RGBA8 image: one value per texel, 24-bit fixed point over ±range, sampled with ToRawShader (no color or alpha conversion).
    • 8-bit channels decode exactly even where children evaluate in half precision.
    • The image is re-uploaded only when its bytes change.
  6. One-shot instances. Rune draws one layer per one-shot. Here a layer keeps a pool and draws each live one-shot as its own instance, over the continuous effect: up to 4 zaps, 3 bursts (merged into the 32 star slots) and 8 ripple slots (4 live plus fading).
  7. Fill tables. rune keeps color stops and metaball paths in a storage buffer. Here the stops ride in uTab (linear rgb, then OKLab) and a stop chosen per pixel is found by a loop, since SkSL indexes uniform arrays only with loop counters. Metaball blobs follow the stops in uTab, and the blue-noise tile is a data table (as bolts and curtains are).
  8. Integer math in fills. Bayer thresholds come from floor and mod instead of bit interleaving (the same matrix; a test checks a flat mid tone dithers to exactly half light pixels with every pattern). Grain gradient and white-noise dither draw their random numbers from the float hash.
  9. Mask pyramid. rune renders the mask into a GPU mip chain and samples fractional levels. Avalonia has no way to draw another visual's composition tree from a custom visual, so the host captures its child with RenderTargetBitmap (on the UI thread, when the child's size or one of its properties changes, or on RefreshMask()), keeps the alpha with room for the glow's reach, and builds six halving, slightly blurred levels on the CPU, once per change. Each level is an image shader mapped back to host coordinates; the shader blends the two nearest levels with four-tap tents, so an animated radius still never steps.
  10. Ripple wash. rune washes the inside of a ripple at 0.05; here it is 0.025. Through the light encoding above, 0.05 tinted a white card about 25%, enough to hide text under it; 0.025 is about 12%, like a state layer. The ring is unchanged.
  11. Backdrop from the surface. rune copies the render target up to the layer into a backdrop texture. Here a backdrop layer snapshots its own region (its bounds, bleed and a 24-DIP margin, clipped to what the compositor is drawing this frame) from the surface it draws into, maps it back to host coordinates with the inverse of the canvas matrix, and binds it as an image shader. Frost blurs that copy once per frame with Skia's blur, on the GPU when there is one. The cost is one region copy per backdrop layer per frame. Inside an offscreen layer the snapshot reads the surface below it, which lacks that layer's content so far. Dither and halftone read the backdrop's tone from the blurred copy (half a cell or a dot pitch), so a cell or dot takes the average of what it covers, and only copy it on the backdrop input.
  12. Trimmed quads. rune sizes an instance quad by its bleed. Here a layer may also give per-side extents (flames and heat haze only rise, glass casts its shadow down), a one-shot state may bound a frame to its live shots (a shockwave's rings), and a backdrop layer copies only the margin it samples. Only the area changes; a test checks that trimmed and full quads produce identical frames.
  13. Render scale. RenderScale below 1 shades into an offscreen target at that fraction of device resolution, in the platform's pixel format and with source-over, so the GPU reuses the pipelines of full-resolution draws, and draws it scaled up with the layer's blend mode.
  14. Aura colors. A short join between neighboring aura colors shows as a seam along a straight edge. Here the colors blend in OKLCh (the hue turns the short way, chroma pulled in to fit the screen instead of clipped), and each pair gets a share of the loop by how different the two look, so the color moves at an even pace all around.
  15. Intensity everywhere. In rune, intensity is a strength only some layers read. Here it is the strength of light layers (up to 3), the coverage of fills (up to 1), and a dimmer on every other layer (it multiplies the layer's opacity), so a transition on Intensity fades any layer. The catalog gives each layer the range that does something.
  16. Liquid metal anchor. The reflection moves with the element by default. Anchor="Window" (rune's behavior) pins it to the window, which also makes it slide over a shape as it scrolls.

Beyond rune-fx

Forty-six layers aren't in rune-fx (motion blur stands in for rune's own version), and Fire's Simulated and Smoke styles stand in for rune's simulated fire. They keep its contract: a pure function of time, free while idle, a reduced-motion pose. They needed these additions:

  • Pointer following. A layer with PointerRange makes its host listen to the window's pointer. The host forwards positions while the pointer is within reach, and null once it leaves. PointerState eases toward the pointer on the render thread, independent of frame rate, and fades in and out. Spotlight and holographic foil use it, and both offer PointAt for keyboard focus or a tour. Each spotlight frame draws only around the light.
  • Direct drawing. Confetti pieces are small rotated rectangles and dots. Skia draws them as shapes (FXLayerState.DrawDirect); a full-quad shader looping over every piece per pixel would cost far more. Each piece is still a pure function of the time since its burst. Pieces fly far past the shape, so each drawn piece reports its bounds (Drew); the visual's render bounds take them in with a margin, and the old bounds are repainted when they shrink, so no shard or spark is left behind on screen.
  • Content in color. The mask capture can keep color (UsesColorMask), so the ambient glow blurs the content's own colors down the same pyramid the mask glow uses.
  • Standing in for the content. Reveal captures the content, holds it invisible with an animation-priority Opacity of 0 (the element's own value is left alone) and plays the transition on the capture. When it ends, the element takes over again in the same UI tick as the layer stops drawing, so no frame shows both or neither. Spoiler reads the backdrop, which already holds the content, so it needs no capture.
  • Motion. Each frame carries the host's window position from its own transform. Motion blur turns that into a velocity (eased over a few frames) and draws the captured content along it, behind the host: a wake rather than rune's blur of the subtree rendered at rest, which Avalonia can't do from a custom visual. It counts any movement, scrolling included. The handler now also checks after each frame whether a layer needs more frames, so a smear fades out once the host stops even if nothing else asks for a frame.
  • A stateful simulation. Fire's Simulated and Smoke styles step a small stable-fluids grid (after Stam: advection, buoyancy, vorticity confinement, a 16-iteration pressure solve) on the render thread at 60 Hz, at most three steps a frame. The heat and smoke fields reach the shader as a data table. A 58×32 grid takes about 0.15 ms a frame (Release). rune runs its simulation on the GPU with ping-pong targets; a CPU grid this small costs less than the round trips would. Unlike every other layer it isn't a pure function of time. On a light surface it draws the flames as color over the smoke rather than as added light, which turned their red edges pink over white, and it fades out before the top and sides of the simulated box. Switching a fire between its procedural and simulated styles changes its kernel and its state, so the host gives it a new renderer; the snapshot carries the state factory, picked on the UI thread, because the render thread can't read the layer's properties. The inspector shows only the settings the current style uses ([FXAppliesWhen]).
  • Pointer paths and bursts. The trail keeps the pointer's last 32 positions with their times. Fireworks, like confetti, are drawn as Skia shapes: each spark is a pure function of the time since its shot.
  • Blur levels. A progressive blur crossfades five copies of what is behind it: sharp, then blurred by 1/8, 1/4, 1/2 and all of Blur (BackdropLevels, bound as uLevel1..3 beside the sharp and blurred copies), one octave apart, so every point sees a real blur rather than a mix of sharp and blurred. Each copy has its own offscreen target (reusing one made the GPU copy it before each draw), and wide blurs are made on a half- or quarter-size copy, which looks the same.
  • Plain color output. emit() writes color with coverage, never the light-surface haze, for layers that show what is behind them or an image (blur, frost, rain, water, glitch, the orb). Frost reads the surface flag itself and draws its crystals darker over light content.
  • Standing in for the content, again. Shatter, Jelly and Page peel share FXStandIn: capture the content, hide it at animation priority, draw the capture, hand it back in the same tick as the layer stops. A capture asked for before the first layout (a peel held from XAML) waits for it. The shatter's shards are a Voronoi cut around the break point, drawn as Skia paths; the jelly is a damped spring plus a bulge spreading from the press; the peel rolls the corner around a cylinder and takes, per pixel, the highest surface that lands on the page.
  • Into a point and out again. The genie works in a frame where the point lies below the content: the sides bend in along a smooth curve that narrows to the neck at the point, then the content slides down that funnel and is cut off where it reaches it. Each pixel maps back to the one content pixel that lands on it, so it is a single shader pass over the capture; the quad grows only toward the point (ExtentFor).
  • Dust. Shatter's dust style cuts the capture into a grid of grains (at most 12,000; larger content gets larger grains). A grain that has not left yet sits exactly in its cell, so what is left is the content itself; the rest drift, curl, rise, gray and fade. All of them go in one DrawVertices call that reads the capture through texture coordinates, rather than a path per grain.
  • A lean on the UI thread. Tilt is the one layer that moves its host: a perspective RenderTransform (at animation priority, so the host's own value comes back) eased on the UI thread's animation frames while it moves, and dropped once it settles flat. It reads the pointer against the host as laid out, not as leaned, so the lean never chases itself. The glare is an ordinary pointer-following shader on the render thread with the same time constant.
  • A shadow from the content. The pointer shadow samples the host's mask pyramid (the content's own pixels) shifted away from a light at the pointer: by distance × elevation / (light height − elevation), eased into MaxOffset, and blurred more as it moves out. With no pointer the light rests above the content and the shadow falls just below.
  • Text without a font. ASCII picks, per cell, a character from a ramp of ten 5×7 dot glyphs (" .-:+=%*#@", ordered by how many dots they ink) packed into the shader as bit fields, by the brightness of the blurred backdrop at the cell's center.
  • Contours at an even width. Topography's lines are where a noise landscape crosses a level; the distance to the level is divided by the slope (finite differences, since SkSL has no derivatives), so a line is as wide in DIPs on a cliff as on a plain, and lines closer than a pixel fade instead of filling in.
  • A projector's clock. Old film steps its weave, flicker, scratches, dust and grain at 18 frames a second, whatever the display runs at; scratches stay for a few of those frames.
  • Melting. Reveal's melt slides each column down at its own pace (slow noise plus a few narrow quick drips) and stretches it, so the top sags into drips and the bottom runs past the content's edge in fingers that fade; the quad grows downward for it.
  • More ways in and out. The radial wipe measures each pixel's angle around the point, clockwise from Angle. Diamonds and halftone dots give each cell its own start by where the cell sits along the sweep, so each grows over half the transition and they come in as a wave; a cell is covered once its diamond or dot reaches the cell's corners. The dots sit on a screen turned 45 degrees, as printed halftones do. The swirl turns each pixel around the point by an angle that falls off from the middle, and samples further out as it hides, so the content shrinks into the twist as it fades. Generate halves its blocks step by step (powers of two of the cell) under colored grain that changes fifteen times a second and settles; each block is the mean of nine samples, since a single sample can miss a thin line altogether (a dark bar vanished at one step), and the blocks are centered on the shape and clipped to its box, since blocks laid from the corner hung off the far edges half empty.
  • Letting go when a host leaves. A presenter that leaves the visual tree drops its custom visual, but the visual's handler lives on in the compositor: with an animating layer it kept asking for frames, and kept its renderers and their GPU copies, for good. Swapping effects in and out (the gallery's pages, an app's routes) piled these up until the frame rate fell from 120 to about 10 over a full benchmark run. The presenter now sends the handler an empty layer list as it leaves, which disposes the renderers and lets it go quiet; it keeps the last list and sends it again if it is attached again.
  • A second simulation. The water surface is the two-buffer ripple scheme on a grid of CellSize-sized cells, stepped at 60 Hz; the pointer's path pushes the water down and a press splashes. Once the surface is flat it clears and stops, so calm water costs nothing.
  • Shader pitfalls found on the way. flat is reserved in SkSL; pow of a negative base is undefined (the jelly's bulge used it and blanked rows of pixels; frost's ridges could hit it), so those square or clamp first.
  • Fills on the child's own pixels. Every fill has UseMask. Rather than a masked variant of each kernel (as Shimmer's), the renderer wraps whatever the kernel draws in a DstIn blend with the mask's sharp level, so any layer that sets ClipsToMask is multiplied by the child's coverage: gradient text, a metal logo. A layer clipped to the mask goes over the child unless its placement says otherwise. The color filter uses the same path.
  • A color filter that reads, not captures. ColorFilter reads what is under it (the backdrop copy the glass layers use) rather than a captured image of the child, so it stays live with whatever the child does: over the child it is CSS filter (the child and what shows through it), under it backdrop-filter. Brightness, contrast, saturate, hue-rotate, grayscale and sepia are CSS's own matrices, on sRGB values as browsers apply them, in CSS's order; then temperature, tint, duotone and invert. A filter at rest is silent (no copy, no draw). It starts as grayscale, so it shows something with no settings; Preset="None" puts it at rest.
  • A grid that answers the pointer. The dot grid eases a pointer and keeps up to four ripples on the render thread (DotGridState) and hands them to the shader in its table; each dot is lit by the nearer of the two and grows a little. A ring lives until it has crossed the shape.
  • States step on a clock that runs forward. Fills share a clock folded every 1024 s (it runs backward for the next 1024) so float noise keeps its precision. (Since replaced: see below.) The states of those layers were given the folded time too, while the pointer and presses they hear about carry the unfolded one. The holographic foil and the liquid progress opt out of the shared clock for this reason; the dot grid, a fill with a pointer and ripples, met it: past 17 minutes of uptime a ripple's age went negative and it never showed. The states now get the unfolded clock and only the shader the folded one (the mesh and metaball states fold their own time), so a fill can keep the shared clock and still ease a pointer. A test fires a ripple at 1500 s and fails without the fix.
  • The distance to the content's edge. Outline and inner shadow need to know how far each pixel is from the edge of the child's own shape, on both sides, and the mask's blurred levels can't tell them: a blurred alpha falls off with how thick the shape is. So a layer can ask for a distance field (UsesDistanceMask), and the host's capture then runs an exact Euclidean distance transform on the coverage, once to the nearest inside pixel and once to the nearest outside one, less half a pixel; pixels on the antialiased edge are placed by their coverage instead. It is one byte a pixel, a quarter of a DIP a step, from 16 DIPs inside to 47.75 outside (sdist() in dist.sksl), sampled with linear filtering. The first version, Felzenszwalb and Huttenlocher's transform on floats with a pass down each column, took 25 ms for a padded 340×190 card at scale 2. Meijster's integer version, with the column pass done as two sweeps over whole rows, takes 4 ms for that frame, 2.4 ms with an ordinary pad, and 13 ms for a 700×500 panel; rows that are all outside (the padding) skip half the work. It runs only when the host captures, never per frame, but a capture follows any change to the child's properties (a hover, say). In the browser without AOT the card took 30 ms, nearly two frames: the row pass called two small helpers per step, and calls are what the interpreter pays most for. Written out inline, with the squared column distances computed once, it takes 14 ms (text, 2 ms). Column distances stop just past the field's range, which keeps the results within the range exact and the squares small; before, a frame more than about 46,000 pixels across overflowed them and crashed. Inside is at least half the content's own strongest alpha, not half of opaque: a review found that text in a translucent color, or a child at Opacity 0.4, had no inside at all (no outline, no inner shadow), and that a mostly opaque but not solid interior read as all edge. Only pixels next to one on the other side now take their distance from their coverage.
  • Outline. Coverage straight from the distance: up to Width outside the edge, or Width centered on it; outside goes under the child, centered over it. The sticker is a thicker outline with a drop shadow read from the same field, offset and softened.
  • Inner shadow. A pixel near an edge facing the light finds the outside a step of Depth toward the light; one near the far edges, a step away from it. The first version shaded the sides too, since a step toward the light along a side also ends near the edge. Weighting each side by how much of the step went toward the edge (the distance it gained over the step) keeps the sides clean. Emboss lights the near edges and shades the far ones; letterpress adds a highlight just outside the far edges, where the page's lip would catch the light.
  • Beam. A quadratic Bézier from one end to the other, bowed sideways by Curvature; each pixel finds its distance to it and where along it it is from Inigo Quilez's closed form (a cubic), so a dash or a pulse moves along the curve, not across the box. The curve's length comes from its sagitta, so dashes keep their length in DIPs as it bows. Pulses live on the render thread (BeamState): those that leave every Interval seconds and those sent with Send(), up to eight heads in the table. With FromElement and ToElement the layer finds the controls' centers in the host after every layout pass and sends a new snapshot when one moved. The quad covers only the curve's hull and its glow. A review found the glow still at 8 to 17 per cent at the quad's edge, a straight cut along a wide beam: the margin is now where the glow has faded out (Beam.GlowReach) and the shader fades it to nothing there. With more pulses on the path than the eight the shader takes (a short Interval), the newest are kept, not the oldest, so a pulse sent by hand always shows. Below a curvature of about 0.003 the closed form's cube roots cancel in 32-bit floats and the path jittered; it is drawn straight.
  • Ink. A stable-fluids grid of its own (InkState), stepped at 60 Hz like the simulated fire's: the pointer's path pushes the fluid and drops ink, a press throws a ring of drops, the flow curls (vorticity confinement), is kept divergence-free by a pressure solve, and carries three dye fields (red, green and blue) that fade. Two things went wrong first. A push narrower than the distance the fluid moves in a step was lost at once, because semi-Lagrangian advection looks back along the flow and finds still fluid there; pushes are now at least four cells wide while the drops of ink keep their size. And a splash that pushed every drop straight out added up to pure expansion, which the pressure solve takes out again, so the ink sat still; the drops now sit apart and lean sideways a little, and the splash spins out like a pinwheel. With no ink left the grid clears and the layer asks for no frames.
  • Silk is a height field of three warped sine folds lit by one soft light, its slope from two nearby samples; the first sheen was a sharp white highlight and read as brushed metal, so it is now broad and only a paler shade of the color. Beams spaces its shafts evenly across the shape (leaning by Angle), so a pixel only looks at the five nearest; each drifts around its place and carries light falling down it, a long tail above a head that softens out. The falling light rides the core only: on the wide glow its end showed as a shelf. Many wide shafts packed close (48 across 300 DIPs) reached past the five nearest and left cuts where the sum stopped, under a wash: a shaft is now no wider than two thirds of the spacing and fades out by two spacings, so they stay separate.
  • A clock that only runs forward, for the shaders too. The fold above (rune's: a triangle wave over 1024 s, which never jumps) suits noise that looks the same either way, but every fill that moves one way ran backward for 512 s out of every 1024 of uptime: rain and snow rose, code rain climbed, meteors flew tail first, the retro grid flowed away. Shader time now wraps forward every 4096 s instead (half a millisecond of float precision at the top; one jump every 68 minutes), and the mesh and metaball states, which work in doubles, take the clock as it is. Checking this turned up a second fault: the weather shader laid its drops out in a frame moving up, so rain and snow rose even on a clock running forward. Tests now check that rain, snow, code rain and beams fall at 20, 700 and 3000 s.
  • Tests on Linux. In a Linux container the suite first could not load Skia at all (its library needs fontconfig; the CI workflow installs it), and then, once in every run, one test failed to set up Avalonia ("a different thread owns it"): xunit ran test classes in parallel, and two of them started the headless session on two threads at once. It never happened on macOS. Test classes now run one at a time; the headless tests share one dispatcher thread anyway, so the suite takes as long as before (43 s), and two Linux runs in a row pass. On Windows 11 on ARM (in a virtual machine, .NET SDK 10.0.114) the CI job passes as it is: both builds with warnings as errors, all 302 tests and the panel audit.
  • Settings in a drawer on a narrow page. Below 760 DIPs the stage would shrink to a strip beside the 316-DIP settings, so the settings fold into a drawer over the stage's right side, opened from a sliders button at the right of the page header. Done, Escape (wherever the focus is) or a press anywhere outside it closes it; that press goes no further, so it doesn't also fire the stage's one-shot. The panel audit checks all of this on a narrow window.
  • The same pace at any refresh rate. Ink and water stepped once more whenever input arrived on a frame with no step due, which on a 120 Hz display is every other frame: the fluid ran about twice as fast while the pointer moved. Input now shows in the frame it lands in without a step. Input that arrives while no frame takes it (a silent layer) merges into the last stroke instead of piling up, and the last of the ink fades out instead of vanishing at the level where the simulation stops.
  • An audit before the first release. The code was read for repeats, names, bugs and cost before it went public; what changed:
    • Names. One meaning per property name across the layers: Speed is the clock multiplier every layer has (seven layers had a FlowSpeed that did the same), a …Speed is DIPs a second, a …Rate is events a second; Duration is one transition, Period one loop, Life one particle, Interval the wait between repeats; color settings end in Color (Background was a color where Avalonia expects a brush), booleans start with Is, and an enum's default is its first member. XAML gets a namespace URL (https://github.com/jsuarezruiz/Nova.Avalonia.FX, prefix fx).
    • Clocks. The shared fill clock never worked: the first thing to read a layer's time (the check whether it animates) fixed its origin before the draw asked for the shared clock, so fills on hosts made at different times were out of step. Only fills wrapped their time; now every shader does (see Clocks above).
    • Show and hide. Reveal, Genie and Shatter share one base class, and the hand-back timer lives in FXStandIn (Jelly, Page peel and Spoiler use it too). Layers written before the content in XAML, the usual order, attached while the host had no child, so a layer that started hidden or peeled did nothing; the host now tells its layers when its child changes. The transitions run on the render clock, not the layer's speed, so Speed can no longer put the timer and the animation out of step, and the reduced-motion duration is decided once, when a transition starts. Shatter no longer throws when its content collapses below 1 DIP, and cuts its shards once per break instead of on every resize.
    • Masks. Any property change on the child recaptured its pixels and rebuilt the distance field, hover included. Changes that can't change pixels are ignored now, a burst of changes captures at most every 100 ms and builds the distance field once it settles, a capture is capped at 4096 px a side and 8 M pixels (by lowering its scale), a failed capture logs and leaves the layer without a mask instead of throwing, and masks are released when the render thread lets go of them.
    • Frames. A setting change re-snapshotted every layer on the host at once; now the changed layer is marked and one sync goes out per frame. Hidden hosts and hosts scrolled well out of view stop asking for frames. A layer that only draws around the pointer repaints only around it, and the border-only layers (border beam, the electric border) shade a ring mesh instead of the whole interior: drawDRRect still runs the shader on the hole on GPU backends.
    • Simulations. Fire, ink and water rebuilt their grid, and the fire re-ran its 90 warm-up steps, whenever the host moved: a host moving every frame cost 29 ms a frame. A move now keeps the grid, a resize resamples it, and the fire warms up only the first time (0.4 ms). The three share one solver. The particle network finds close pairs through a grid instead of testing every pair, and it and the electric bolts no longer allocate per frame.
    • Shaders. Helpers written several times moved into shared parts (inside, fill_mask, fbm, breathe, dat_bilerp, the flame ramp, the sheen); loop limits are filled in from the C# constants instead of copied by hand; a glow at radius 0, an aura of gray, reversed smoothstep edges and pow of slightly negative noise could all produce NaN on some GPUs.
    • Gallery. The home page's 80 tiles are one control, the per-layer switches on the effect page are one table, and --sweep renders every effect on every target in both themes so each demo can be checked by eye.
    • Every demo on every target. Two rounds of that sweep, looked at cell by cell, found that most of what read badly was the staging, not the effect: a field over a fill kept the theme's placeholder color (which Fluent also fades to half), pictures only reached a card, a fill on bare text painted the text's whole box, a panel had no room for a glow or a flame, and one ink was chosen per effect wherever its label sat. Each effect now offers only the targets it suits, follows the letters on bare text where it can (a fill's mask, a mask glow), picks its ink where the label sits, and the pointer layers move on their own until the pointer arrives. The effects that needed it changed too: liquid metal's horizon no longer breaks into blotches, an inner shadow is soft and shows a lit lip on dark, the foil, fire, electric bolts, fireworks and a dissolve know a dark surface from a light one, and fog, aurora, metaballs, starfield and the particle network scale with the shape.
    • Measured again after it. On the same machine, GPU costs held or dropped (Electric, CRT, chroma split, glitch and water most), a 700×500 panel costs about half what was noted before, and in Chrome every effect holds 57–60 fps with the CPU four times slower except the interpreted simulated fire (44). Three readings looked like slowdowns and weren't. Confetti's CPU time (0.11 then 0.36 ms) and the browser's compiled .NET time swing two to three times from run to run with the same code. First frames read 20–200 ms in any run where the system's Metal shader cache had dropped the layers' pipelines (after the restart, and again the next morning) and 2–10 ms in the run after: WarmUpAsync compiles the SkSL, not those pipelines. The bench's compare now times a layer that looks slower up to twice more and keeps its best run, and every measure starts from a fresh layer: Fire timed again after fire:Simulated had kept the simulated style and read a third of its cost. It also keeps its window on top and deaf to the real pointer, and exits with 2 when layers ran far under the others' frame rate or drew nothing, as a covered window or one on another desktop does on macOS.
    • Paces that carry on. Only Speed changed smoothly. The 23 settings that set a pace of their own (flow, drift, fall and wave speeds, and the flicker, meteor and glyph rates) were multiplied by the clock in the kernel or the CPU state, so a change while the layer ran moved the pattern to where the new pace would have put it from the start. Each is now a phase on the layer clock, kept continuous the way the clock is (FXPhase). A kernel reads it from a slot the renderer fills each frame (FXUniformBlock.Phase), and a CPU state reads the same phase by index, so aurora's curtains and rays, and the mesh gradient's points and warp, stay together. A phase wraps at 4096 s × the top of its setting's range, so at full pace it keeps the clock's precision and wraps as rarely. A test changes each one mid-run and checks that the next frame matches the last; run against the old behavior, all 23 fail, with 129 to 24,302 pixels jumping. Electric moved with StrikeRate in three places: the charged beads in the kernel, and the charged hairline and the border bolt's crawl on the CPU. All three read its phase now, and the charged style is a 24th case of the test. Left as they were: rates of events (the strikes themselves, GlitchRate, a glitch's Frequency), where a change can add or drop one strike or burst, and the speed of something already under way (a ripple's RippleSpeed, a jelly's Frequency).
    • Dead and repeated code. A pass with the compiler's own symbol lookup (every declaration in the library and the samples against every reference in every project, tests included) found nine internal members that nothing used, among them a distance lookup "for tests" that no test called; it also kept a second copy of every mask's distance field in memory. They are gone. Halftone and liquid progress no longer compile fill.sksl, which neither calls. Every other shader module, function and style branch is used. The repeats worth a shared helper were folded: the glow kernels' breathing and cooling (glow_light), Electric's fork light in the kernel and its halo cache and border setup on the CPU, and the tests' window helpers. Left as they are: the styled-property declarations every layer needs, and a few short repeats where a helper would cost more to read than it saves. FXHost.RefreshMask and Pulse.PingTo, documented but called nowhere, have tests now.
    • Quadratic work and leaks. Every nested loop in the library whose bounds both grow with the data was read. All are linear in what they cover (pixels, grid cells, live pieces), with one exception: Shatter cuts each piece's cell against every other piece, once per break. That takes no longer at its 120-piece maximum than at 24 (the break's frame is 3.5–4 ms either way, most of it capturing the content), so it stays. Every event a host or a layer hooks (the window's pointer, the static settings event, layout) is let go on detach, every timer stops, every cache is bounded, and every native Skia object is disposed or replaced in place. A test now proves it: every layer is shown, hovered, pressed and drawn, then removed from a window that stays open, or left in one that closes, and the host and the layer must both be collected. A planted leak (the host keeping its settings handler) fails it for every layer. Avalonia keeps a window it just closed after a press for a moment (a plain window with nothing of ours in it too), so the test lets the dispatcher run its timers before it collects.

5. Review of the port

Three independent line-by-line reviews compared every shader and CPU builder with rune's WGSL and Rust. They found no transcription errors. They did find these, all now fixed:

  • finish() encoding. It treated linear light as sRGB-space coverage, so faint glows, rings and sheens were up to about 10× too dim. It now encodes as rune does.
  • Shader lifetime (crash). Disposing a layer's SKRuntimeShaderBuilder disposed the shared, cached effect. Removing a layer, or moving it between hosts, freed the shader under every other layer of that kernel.
  • One-shots. A full ripple pool cut its oldest ripple instead of fading it. Zaps and bursts replaced the continuous effect, all looked identical, and re-triggering cut the live one.
  • Clocks. Fills used per-host clocks (seams between window-anchored neighbors), unfolded time, and time 0 instead of CALM_T under reduced motion. Shimmer froze instead of breathing under reduced motion. A layer at speed 0 kept ticking.
  • Bounds and robustness.
    • Fills had no anti-aliasing bleed.
    • Pulse breathe's bleed was too short.
    • Electric stopped animating with no strikes.
    • NaN parameters blacked a layer out.
    • The data image was re-uploaded every frame.

Building the spotlight found one more, now fixed: on a light surface, a white or gray light came out black, because the haze takes its hue from the layer's color and white has none. It now stays white.

A report of jitter while scrolling led to one more change. The host used to send its window position (for window-anchored fills) from the UI thread after each layout pass, so a scroll or animation that moves a host without one left the position stale. The render thread now reads it from each frame's transform. A test checks that a host scrolled into place draws exactly as one laid out there. On this machine, the gallery's --scroll-demo, which scrolls Home a few DIPs every frame, holds 120 fps (median 8.3 ms, nothing over 20 ms) with either version. With real mouse-wheel input (each tick moves the page 10 DIPs in one frame), a recording of the shimmer, aurora and liquid metal tiles shows the frame caught mid-scroll matching the settled frame as closely as two still frames do: nothing is drawn a frame late. Trackpad momentum scrolling hasn't been recorded.

Two findings are left open:

  • Preset priority. Presets apply at template priority, which Avalonia ranks above a plain type-selector style. Treating presets as control themes would fix that.
  • Mesh rest points. MeshGradient's rest points aren't exposed yet (rune has points).

6. Roadmap

Next. These fit the current architecture.

  • Dither and halftone over an image (rune's Image input). The backdrop input is done; an image would bind the same way, as an image shader in place of the backdrop copy.
  • Simulated fire and smoke on the GPU. Fire's simulated styles run a small grid on the CPU now; rune's firesim.wgsl steps a finer one on the GPU with ping-pong targets.
  • Fire in two passes. It is the heaviest kernel per pixel (eight noise evaluations). RenderScale already quarters its cost, but it softens the embers along with the flames. Shading the flames at half resolution and the embers at full would keep them sharp.

Done: effects that read the backdrop. Glass, fluted glass, heat haze, shockwave, CRT and chroma split read what was drawn beneath them through lease.SkSurface.Snapshot(bounds) (divergence 11). Two other routes were weighed: SKCanvas.SaveLayer with a backdrop filter is limited to Skia's built-in filters (SkiaSharp 3.119 has no runtime-shader image filter), and support in Avalonia itself (below) would also cover offscreen layers.

Motion blur draws a wake from the content's capture. A true blur of the content itself still needs the moving subtree rendered at rest.

Out of scope for now. rune-light-style lighting (an SDF field, soft shadows, GI) is a different scale of project and would be its own package.

7. What Avalonia itself could add

These would remove the host wrapper and make the backdrop family exact:

  • An extensible IEffect backed by a runtime shader with uniforms, applied per Visual, so Effect="{fx:Glow ...}" works on any control.
  • Backdrop access for composition custom visuals: an image of what lies beneath the visual's bounds, the equivalent of rune's effect_backdrop slot. The surface snapshot used now is right on the window's surface but not inside offscreen layers.
  • A way to render an element's content to an image on the render thread, for mask glow and motion blur.
  • A platform reduced-motion preference for FXSettings.ReducedMotion to follow.

In the browser

The gallery also runs in the browser (samples/Nova.Avalonia.FX.Gallery.Browser), set up like Nova.Avalonia.UI's: a shared gallery library, a desktop app and a WebAssembly app that shows the shell as a single view. SkiaSharp's WebAssembly build includes the runtime-effect compiler, so the SkSL kernels run on WebGL as they are: a ?check start compiles all of them in about 1.4 s with no failures; a ?verify run opens all 117 effect and style combinations, fires each one-shot and finds every one drawing (counted by FXDiagnostics, waiting for the first draw, since a browser tab in the background paints only a few frames a second); and a ?tour through every page (firing each one-shot) showed every effect drawing as on the desktop, including the backdrop copies and their blurs, the mask pyramid, the captures (shatter, reveal, genie) and the pointer layers. Nothing in the library needed changing: the browser runs .NET on one thread, so the compositor's work and the UI share it, and FXSettings.WarmUpAsync simply compiles on that thread. Two notes from setting it up: the repository now pins the .NET 10 SDK (10.0.100 or a later 10.0 feature band, never a preview), as Nova.Avalonia.UI does (with the .NET 11 preview's WebAssembly tools, a Debug build left SkiaSharp's native code out); and the desktop-only tools moved with Program into the desktop app.

Timing in the browser

?bench runs the desktop bench's measurement (BenchProbe, now in the shared gallery) in the browser: each effect over the drifting scene for 2 s, firing its one-shot every 0.35 s, counting the frames painted and the 95th-percentile frame time, with each draw's CPU time from FXDiagnostics. Three things shaped it:

  • A hidden page paints a frame a second. The browser pane, a background tab or a covered window throttles requestAnimationFrame, and the page may still report itself visible. The bench measures the browser's own frame rate with the app hidden (so a slow effect is not mistaken for a hidden page) before and after each effect, waits while it is under 20 fps, and times an effect again when the page was hidden by its end. scripts/browser-bench.mjs runs it in a headless Chrome, which paints at 60 Hz on the real GPU (ANGLE on Metal here) whatever is on screen, and drives Chrome's CPU throttling through the DevTools protocol.
  • There is no GPU time in WebGL. A synchronous flush returns without the GPU having finished (every layer read about 0 ms), so the frame rate is the measure.
  • The first run's slowest effects were the gallery's. Liquid progress (11 fps), Shatter, Page peel, Reveal, Spoiler and Genie (22–39 fps) cost little per draw but had 100–300 ms frames: each show, hide or level change rebuilt the gallery's settings panel to show the new value, which takes a frame or more interpreted. The page now updates only that editor (and rebuilds when the change shows or hides other settings); all six went back to 59–60 fps.

What was left is .NET code: the browser interprets it unless the app is compiled ahead of time. The first numbers came from dotnet run, whose Release build still had debugger support on (debugLevel -1 in its boot config), which turns off the runtime's optimization of interpreted code (the jiterpreter): there, on the M4 Max, the simulated fire ran at 20 fps, Dust at 22 (6.6 ms a frame for its 6,000 grains) and Electric at 51 (3.8 ms a bolt), and with the CPU throttled 4× the whole gallery fell to 40–50 fps. The gallery now builds Release with WasmDebugLevel 0, as a publish does. Published and interpreted, every effect ran at 59–60 fps (Dust 2.5 ms, Electric 1.0, the fire 0.8); with the CPU throttled 4×, 60 of the 66 stayed at 52–60 fps and the layers that work in .NET code dropped: the simulated fire to 9 fps, Electric 22, Dust 33, Fireworks 43, Shatter's shards 51 and Melt 52. Compiled ahead of time, those cost 0.14, 0.10 and 0.35 ms (fire, Electric, Dust), and with the CPU throttled 4× every effect stayed at 54–60 fps (Fireworks the lowest, 1.7 ms of CPU for its sparks). The cost is the download: 9.2 MB Brotli-compressed instead of 5.8 MB. The browser gallery compiles ahead of time on a Release publish, and the README recommends it for apps that use those layers on slower machines.

The CPU layers, written for the interpreter

Timed piece by piece in the browser (with the CPU throttled 4×, interpreted), the cost was in a few loops, and the fix in each was to do the same arithmetic with fewer calls or less often:

  • The fire simulation took 12 ms a step, up to three steps a frame (9 fps), and 1 s for its 90-step warm-up when it first shows. Every cell read its neighbors through I(x, y), a method call the interpreter can't fold away: the 16-iteration pressure solve alone made 275,000 calls a step. The loops now index the arrays directly, with the arrays in locals and the clamps inline: 5.4 ms a step, 43 fps. The warm-up still runs on first show (half a second at 4×, interpreted).
  • The data tables (Electric, the fire, Water, Aurora) are encoded into texel bytes every frame; the loop called Math.Round, Math.Clamp, Math.Abs and Math.Max per value. It now rounds half to even inline, writes each texel as one word, and a table nobody wrote to since its last upload (the same table drawn again) isn't encoded at all. A table that keeps changing stops being compared with its last upload after a run of changes (the comparison only saves an upload that would carry the same bytes) and is checked again every 30 frames.
  • Electric built every bolt every frame: midpoint displacement into new lists through delegates, a resample with a Tanh per sample, a three-pass blur calling a closure per sample, and a crawl taking gradient noise per sample, each noise call 12 hashes and 4 sines and cosines. Bolts and their halos are now cached per strike (a strike holds its shape for several frames, a zap for its life), the blur wraps its indices inline, and the crawl and the charged hairline take their noise along a row with FXMath.GNoiseRow, which works each lattice column's gradients out once. Building went from 7.8 ms to 1.0 ms a bolt: 22 to 38–49 fps.
  • Dust wrote 24,000 vertices a frame through SKPoint and SKColor constructors, with Math.Clamp, Math.Round and a Smooth call per grain, and cut its 6,000 grains on every break with seven hashes each through nested calls. The vertices are now written as raw floats and color words, the clamps and rounding are inline, and the cut reuses its arrays and the grid's corners when the content's size hasn't changed, with the hash written out: 8 ms to 3.3 ms a frame, 43 ms to 13 ms a cut, 33 to 57 fps.
  • Fireworks drew each spark as two antialiased round-capped stroked lines (halo and core), several hundred Skia path draws a frame. Batching them by color and width saved nothing, since Skia still strokes every line, and was undone. On the GPU the sparks are now soft round-ended strips: three quads each (half a disc, a sliver of its middle stretched along the streak, the other half), textured with one antialiased, mipmapped 64-pixel disc, the color in the vertices, all in one DrawVertices a frame. Halos and cores keep their widths and alphas, and GPU screenshots in Chrome, old and new side by side, look the same. CPU time per frame went from about 0.9 to 0.35 ms in Safari and from 0.29 to 0.09 ms on the desktop; in Chrome with the CPU 4× slower, from 26–37 to 35–44 fps. Two things keep the strips off Skia's CPU renderer: it drops triangles with no area in the texture (the strip's middle was first a single texel column, and only the caps drew), and it doesn't blend a texture's mip levels, so a disc shrunk to a few pixels comes out jagged. Without a GPU the sparks stay stroked lines, exactly as before, which is also how the tests render them.

Every change to the loops above kept the output exact: a probe rendered fire, Electric (all three styles), Dust, the shards, Fireworks, Water, Aurora, Confetti and the particle network frame by frame and the pixel hashes matched before and after (Fireworks before its sparks became strips; without a GPU it still draws exactly as before). Three tests keep it so: the row noise against GNoise, the table encoding against Math.Round, and Electric's tables with and without the bolt cache. On the desktop the bench finds all of them within noise of the baseline (Electric's and the fire's CPU time went down: 0.022 to 0.009 ms, 0.025 to 0.007 ms).

Safari

Safari 27 on the same Mac runs everything: ?verify finds all 117 effect and style combinations drawing, with no errors or warnings, and a tour through the pages most likely to differ (glass, fluted glass, frost, progressive blur, heat haze, liquid metal, holographic foil, Voronoi, aurora, fire, topography, ASCII, halftone, old film, ambient glow) shows them as in Chrome: no banding from lower precision, refraction and blur intact.
