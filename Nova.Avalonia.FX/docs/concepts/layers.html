Layers and hosts

Every effect in Nova.Avalonia.FX is a layer, and every layer lives in a host. This page covers how the two work together.

The host

FXHost is a control that takes one child (its Child, the XAML content) and draws a list of layers around it (its Layers). It keeps two drawing surfaces: one under the child and one over it.

<fx:FXHost CornerRadius="16">
    <fx:FXHost.Layers>
        <fx:Glow Color="#7c5cff" Radius="18" />
        <fx:Grain Amount="0.08" />
    </fx:FXHost.Layers>
    <Border Width="240" Height="120" Background="#15171c" />
</fx:FXHost>

The layers follow the child's shape: its bounds and corner radius. The corner radius comes from FXHost.CornerRadius when it is set, or else from the child itself when it is a Border or a templated control. The shape uses one radius for every corner (the top-left one). Set CornerRadius="999" for a capsule or a circle.

Light that spills past the child (a glow, a pulse, flames) is drawn outside the host's bounds, so any clipping ancestor cuts it: a ScrollViewer, a Border with ClipToBounds, or Fluent's ContentControl, which clips by default. Leave room around the host inside such containers, or set ClipToBounds="False" where that is safe.

A layer draws with its host, so a later sibling covers anything the layer draws past the host. Give the host a higher ZIndex when, for example, a ping should land on top of another control.

A layer can be in one host at a time. Adding a layer that is still in another host's Layers throws an InvalidOperationException: remove it from the first host, or give each host its own layer.

How layers stack

Each layer draws either under the child or over it. Its Placement decides which:

Placement Where the layer draws
Auto (the default) The layer's own default: light that spills out goes under, overlays go over.
Under Behind the child, like a background or a glow.
Over On top of the child, like a sheen or grain.

With Auto, glows, the pulse's rings, fills, glass and backgrounds go under the child; the shimmer, grain, sparkles, lightning, ripples, distortions, transitions and the pointer layers go over it. A fill with UseMask goes over the child, since it paints the child's own pixels (see Content masks).

Within each placement, layers paint in the order they appear in Layers: the first one is painted first, and each later one on top of it.

<fx:FXHost.Layers>
    <!-- Under the child: the glow first, then the fill on top of it. -->
    <fx:Glow Color="#22d3ee" />
    <fx:MeshGradient Preset="Lagoon" />
    <!-- Over the child, the shimmer's own default. -->
    <fx:Shimmer />
</fx:FXHost.Layers>

Blend modes

BlendMode sets how a layer composites onto what is beneath it:

Blend mode Effect
Normal (the default) Premultiplied source-over.
Screen Light that brightens without ever exceeding white.
Plus Additive light.
Multiply Darkens by the layer's color.
Overlay Multiplies or screens, depending on what is beneath.
SoftLight A gentler overlay.

Light layers already draw as light over a dark surface. For pure additive light, set BlendMode="Plus" or "Screen". A transparent caustics layer with BlendMode="Screen", for example, lights the content under it:

<fx:Caustics WaterColor="Transparent" BlendMode="Screen" Placement="Over" />

Properties every layer has

Every layer derives from FXLayer and has these properties:

  • Intensity is the strength of light on light layers (aurora, electric, fire, glow, grain, light leaks, light rays, pulse, shimmer and sparkles), up to 3; the coverage of fills, up to 1; and a dimmer that fades every other layer. So a transition on Intensity fades any layer in and out.
  • Opacity fades the layer, from 0 to 1.
  • Speed multiplies the layer's clock, from 0 to 4. Changing it never makes the animation jump, and at 0 the layer stops. A layer's own pace settings (a FlowSpeed, Drift, FallSpeed and the like) run on that clock and don't make it jump either: the pattern carries on from where it is. The show and hide transitions run on their Duration instead.
  • Seed picks the random layout of layers with randomness (noise, scattered stars, confetti). Two layers with different seeds look different; the same seed always draws the same frames.
  • Placement and BlendMode, described above.
  • IsActive switches the layer off: it draws nothing, costs nothing, and ignores presses and the pointer.
  • RenderScale shades the layer at a fraction of the display's resolution (0.25 to 1) and scales it up. It is meant for large, soft, heavy layers; see Performance. Layers drawn as shapes (confetti, fireworks, shatter, particle network) don't use it.

Each layer also reports ReadsBackdrop, which is true for layers that read what is drawn behind the host (see below).

Property Type Default Description
Intensity double 1 How strong the layer is. Light and fills read it as their own strength (a glow's brightness, up to 3; a fill's coverage); on other layers it is a dimmer that fades the layer, like Opacity. 0 draws nothing. Range 0–3.
Opacity double 1 How opaque the whole layer is: 0 invisible, 1 as drawn. Range 0–1 (0–100%).
Speed double 1 Multiplies the layer's clock. Changing it never makes the animation jump. Range 0–4.
Seed int 1 Picks a variation of the layer's random pattern (its noise, where pieces fall); the same seed always draws the same picture. Layers without randomness ignore it. Range 1–999.
Placement FXPlacement Auto Where the layer draws: behind the host's child, over it, or (Auto) where the layer usually goes. Values: Auto, Under, Over.
BlendMode FXBlendMode Normal How the layer combines with what is beneath it: painted over it (Normal), or blended as light or color. Values: Normal, Screen, Plus, Multiply, Overlay, SoftLight.
IsActive bool true Whether the layer draws. Off, it draws nothing, costs nothing and ignores the pointer and presses; a transition layer then shows or hides its content at once.
RenderScale double 1 Shades at this fraction of the display's resolution and scales the result up: 0.5 shades a quarter of the pixels. For large, soft layers (a window-sized aurora or swirl), where the cost grows with the area; edges and grain soften. 1 (the default) is full resolution. Range 0.25–1 (25–100%).

Not every setting applies to every layer, or to every style of a layer: Seed and Speed only matter on layers with randomness or motion, and many settings belong to some styles only. The gallery's settings panel shows only the settings that do something, from what FXCatalog knows.

Idle layers cost nothing

A layer asks the compositor for frames only while it moves. A layer at rest draws once and then asks for nothing:

  • still layers, such as a plastic fill, a static grain or a glow that doesn't breathe;
  • layers that are switched off, or at an Intensity or Opacity of 0;
  • one-shot layers between shots: a glitch draws nothing until it fires;
  • pointer layers while the pointer is away: a spotlight draws nothing and costs nothing until the pointer arrives;
  • the small simulations (simulated fire, ink, water) once they have settled or emptied;
  • every layer of a host that is hidden, or scrolled out of view.

When you change a setting, only that layer is snapshotted again, and the host sends at most one update per frame.

Layers that read the backdrop

Some layers show or change what is drawn behind them: glass, fluted glass, the magnifier, progressive blur, frost, rain on glass, water, heat haze, shockwave, CRT, chroma split, glitch, old film, ASCII, the color filter, the spoiler (except its Solid style), and dither or halftone with Input="Backdrop". Their ReadsBackdrop is true.

Such a layer copies its region of the window's surface just before it draws. Glass and FlutedGlass sit under the child, so they bend what is behind the host; the distortions sit over it, so they bend the child too.

Inside an offscreen layer (an ancestor with Opacity below 1, an effect, or a clip that needs a layer), the copy can't see that ancestor's content. Keep such ancestors opaque.

Styles, bindings and presets

Layers are styled elements. They join the host's logical tree, so they inherit its DataContext, and styles, bindings, dynamic resources and transitions apply to them like to any other property:

<fx:FXHost Classes="hover">
    <fx:FXHost.Layers>
        <fx:Glow Color="{DynamicResource SystemAccentColor}" IsLit="{Binding IsOnline}" />
    </fx:FXHost.Layers>
    <Border Width="200" Height="80" CornerRadius="12" Background="#101217" />
</fx:FXHost>

<Style Selector="fx|FXHost.hover fx|Glow">
    <Setter Property="Intensity" Value="0.2" />
    <Setter Property="Transitions">
        <Transitions>
            <DoubleTransition Property="Intensity" Duration="0:0:0.3" />
        </Transitions>
    </Setter>
</Style>
<Style Selector="fx|FXHost.hover:pointerover fx|Glow">
    <Setter Property="Intensity" Value="1.3" />
</Style>

Many layers have a Preset or a Style that sets several values at once. Presets apply at template priority: a local value, or a style with a class or pseudo-class, wins over a preset; a plain type-selector style does not.

Fills painted from a list of colors (mesh gradient, swirl, waves, grain gradient, voronoi, metaballs, dither and bokeh) take up to six colors in Colors. Unset, they use the preset's palette. In XAML, separate the colors with commas, semicolons or spaces; hex values, color names and CSS forms such as rgb(43, 27, 90) all work:

<fx:MeshGradient Colors="#2b1b5a, #ff6f91, #ffc46b" />

The catalog

FXCatalog describes every layer type: its id, display name, summary and parameters, with their ranges, units, choices and the styles they apply to. The gallery builds its navigation and settings panel from it. ToXaml writes a layer back as XAML, as its preset or style plus the values that differ:

using Nova.Avalonia.FX;
using Nova.Avalonia.FX.Catalog;

foreach (var info in FXCatalog.Layers)
    Console.WriteLine($"{info.Id}: {info.Name}, {info.Parameters.Count} settings");

var glow = new Glow { Style = GlowStyle.Neon, Radius = 20 };
Console.WriteLine(FXCatalog.ToXaml(glow)); // <fx:Glow Style="Neon" Radius="20" />
